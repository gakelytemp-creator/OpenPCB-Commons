# Preparatory Learning Course

> **Grow curiosity before specialization. Turn knowledge into a tool before asking anyone to carry it.**

This folder is the educational nursery of OpenPCB Commons.

OpenPCB Commons collects real boards, measurements, circuit structures, repair knowledge, reusable parts, and investigation methods. A commons stays alive only if new people can enter it without being frightened by accumulated complexity.

The course is not primarily for examinations. Its purpose is to make electrical-engineering knowledge **alive**: understandable, memorable, usable, recombinable, and friendly enough that the learner can carry it into unfamiliar problems.

## Four complementary paths

Each important topic should be available through four connected views:

1. **Discovery** — reconstruct the situation in which a phenomenon became surprising. Give the learner enough evidence to form an interpretation before revealing the historical resolution.
2. **Principles** — build a deep intuitive model through experiments, analogies, counterexamples, and interactive scenes. State explicitly where each analogy stops working.
3. **Formalization** — compress the understood structure into symbols, equations, units, graphs, and calculational tools.
4. **Applications** — show where the principle lives in real technology, industry, instruments, machines, and everyday devices, and what humanity would lose without it.

The paths reinforce one another. A learner may enter through history, intuition, mathematics, or usefulness, but all roads should meet at the same underlying structure.

## Interaction first, media second

The same lesson may exist at several levels:

- printed comic or magazine pages;
- image/slideshow lesson;
- narrated video;
- browser interactive;
- phone-assisted voice/camera session;
- desktop 3D simulation;
- VR/AR scene.

The lowest-tech version must still preserve the conceptual core. Richer hardware should add freedom, not become a prerequisite for learning.

## Teacher / LLM role

An LLM may participate through AISocket or another bounded interface as a live guide inside the learning environment.

Its role is not to spoil discovery by supplying the answer immediately. It should be able to hear the learner's interpretation, inspect the current experiment state, request another comparison, explain the boundary of an analogy, help reconstruct a forgotten formula from principles, and connect a virtual experiment to a real build shown through a camera.

A phone may act as a personal microphone, camera, and controller. Stronger systems may add richer 3D or VR interaction.

## Optional challenges and real rewards

Questions and challenges should not block the main learning path.

They may live in an optional challenge area. Where practical, rewards can be real tools that expand the learner's next range of action: components, breadboards, sensors, multimeters, logic analyzers, or other age-appropriate laboratory equipment.

The reward should become part of the next stage of learning.

## The bridge into OpenPCB Commons

curiosity
→ discovery
→ principle
→ formalization
→ application
→ simulation
→ schematic
→ PCB
→ measurement
→ repair / reuse / new design

A learner should eventually move from a lesson into the real Commons: examine a board, recognize a circuit pattern, measure it, contribute evidence, reuse a part, and leave a clearer road for the next person.
